# Launch materials

Suggested introduction:

InstrumentZero turns supported measurement questions into calibration steps, executable analysis, uncertainty estimates and the next proposed experiment. The local Lab handles force–deflection data and acoustic recordings without an API key. It ships authentic recorded examples, complete evidence exports, and a 5,400-trial adaptive-design study, including the cases where conventional methods nearly match adaptation and where learning adds no practical benefit.

This first research preview is explicit about what remains: total physical calibration is not established by a narrow fit, and real-device webcam/microphone acceptance still needs supervised testing. The measured nickel-sensor example is useful partly because the model fails under declared noise assumptions.

Repository: https://github.com/nazeeh111/InstrumentZero

Walkthrough: the release MP4 is a sequence of unaltered screenshots of actual running product states. It shows a synthetic control, compiled procedure, recorded-audio analysis and a rejected recorded stiffness model. It is not footage of a new physical experiment. No microphone/camera recording, voice clone, paid model or stock scientific footage was used. Editable FFmpeg source and screenshots are retained under `assets/launch-v0.1/`.

These materials are prepared for voluntary community sharing. No external outreach, manufactured stars or promotional messages are part of this release.

## v0.2 recording-based validation update

The updated Lab adds public PTB calibrated acoustic reference records, a sequential stiffness replay using only available real observations, and generated-media acceptance tests of production acquisition code. The replay reduces held-out reference error on its small recorded pool and ties a strong conventional endpoint choice. Simulations expose hidden-clock failures rather than certify arbitrary audio. New images/video show the actual recorded-data workspace; they are not footage of a new physical experiment. See NO_EQUIPMENT_VALIDATION.md for precise evidence boundaries.
