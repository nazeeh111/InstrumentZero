# InstrumentZero Edge: simulation model and scope

InstrumentZero Edge is a complete local signal and processing-placement simulation project. Hardware is not required for installation, use, validation or completion. The MCU adapter and recording imports are retained as optional extensions and historical engineering work. They are not evidence of physical measurements and are not completion gates for this project.

## What the model means

The custom source generates an analytic decaying sinusoid, sampled on an ideal clock:

```text
y(t) = A exp(-alpha t) sin(2 pi f t + 0.3) + epsilon(t)
t[n] = n / sample_rate
epsilon[n] ~ Normal(0, noise_rms^2)
```

`f` is the damped oscillation frequency in Hz, `alpha` is decay per second, and `A` and `noise_rms` use the source's declared units. The first channel uses this signal; additional channels scale it by `1 - 0.2 × channel_index`. Float32 samples and rounded integer-microsecond timestamps enter the same bounded graph and packet path as the presets. Noise is generated by NumPy's seeded default generator. Exported raw bytes, source, dependency lock and manifest are the durable reproduction record; a seed alone does not replace them.

This is a signal model useful for testing algorithms. It is not a finite-element beam solver, a material model, an analog sensor model or a claim about a real cantilever. Presets A and B are synthetic 17.25 Hz and 22.5 Hz cases; their internal historical scenario names remain `mount_a` and `mount_b` for compatibility.

| Custom parameter | Bound |
|---|---|
| Frequency | 0.1 Hz to sample_rate/2 − 0.1 Hz |
| Decay | 0 to 5 per second |
| Gaussian noise RMS | 0 to source full scale / 4 |
| Initial amplitude | 0 to source full scale |
| Seed | Integer 0 to 2³² − 1 |
| Duration | 1–30 s, bounded by 200,000 frames |

Input validation happens before generation. A permitted parameter does not guarantee an identifiable measurement: noise can obscure the signal, a frequency can fall outside the estimator passband, rapid decay can leave too few cycles, and amplitude plus noise can clip. Those are useful rejection experiments. Zero decay may support frequency while withholding damping. A model change or seed edit invalidates the previous result/export. The simulation identity binds specification, scenario, model parameters, seed and duration; the graph has its own separate specification identity.

## Two different checks

The analytic truth check compares the selected estimate with the declared model. Its expected damping ratio is `alpha / sqrt(alpha^2 + (2 pi f)^2)`. It reports absolute frequency error and relative damping error against the declared estimator budgets. A `frequency_only` result means frequency passes while damping was withheld; it is not a full damping pass. Zero expected damping has no defined relative error. Non-single-mode/no-signal/fault scenarios have no single-mode analytic truth check.

The processing check compares the C core with NumPy float64 calibration and SciPy filtering on the same input. Its Δf is a numerical implementation comparison, distinct from error against the analytic model. Neither check is an independently acquired physical measurement.

## Placement and costs

Raw-host, calibrated-edge and filtered-edge paths process equivalent input through the actual C core and IZP1 encode/decode path in software. The deterministic planner enforces modeled transfer, memory, delay and numerical-error budgets. It can leave processing on the host, particularly when raw validation would require an additional stream. Local primitive timings are measured host proxies, not MCU measurements. Data-byte comparisons include packet framing, timestamps and CRC; startup/control traffic and electrical framing are outside those comparisons. Power and physical latency are not simulated or claimed.

## Reproduce a custom experiment

```sh
instrumentzero edge simulate --scenario custom_ringdown \
  --frequency 18.6 --decay 0.8 --noise 0.0006 --amplitude 1 \
  --seed 6001 --seconds 8 --export custom-evidence.zip
```

The installed interface exposes the same controls. Export into a new file, extract a trusted archive into an empty directory, install its pinned `requirements.txt`, and run `python recompute.py`. The bundle retains model/seed, samples, timestamps, protocol, compiled coefficients, cost profile, results, source and hashes. Recompute checks numerical results and the analytic truth report using explicit floating-point tolerances. An unsuitable signal's rejected result remains exportable. A clipping failure cannot produce a numerical result.
